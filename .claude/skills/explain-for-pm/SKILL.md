# Explain for a PM

## Structure (keep this order, max ~250 words)

1. **In one sentence:** what this part of the product does for users.
2. **How it works:** 3-5 short points in everyday language. Use one analogy from office life if it helps.
3. **Why it matters:** user impact, business rules it enforces.
4. **Risks and limits:** what could go wrong or isn't handled yet, stated plainly.
5. **Questions a PO might want to decide:** 1-3 product questions the code raises (e.g. "should back-to-back bookings be allowed?").

## Rules

- No jargon. If a technical term is unavoidable, explain it in brackets once.
- No code in the answer unless the reader asks for it.
- Be honest about uncertainty: say "it looks like" when you're inferring.
